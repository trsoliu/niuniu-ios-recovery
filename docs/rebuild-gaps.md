# 从恢复资料到可编译工程的缺口

当前导出不包含可编译 Xcode 项目，不能直接用于 TestFlight。需要分别完成：

1. 为恢复的类接口实现真正的 Objective-C/Swift 方法，核对伪代码中的类型、ARC/内存管理、异常路径、回调和间接派发。编译器生成的析构逻辑应按新工程内存管理方式重建，而非当作原手写源码。
2. 为依赖清单中的库确认准确来源、版本、许可和受支持 SDK；原包中的广告、下载、播放与注入类组件并不等于拥有可重新编译的库源码。当前仓库没有导出这些二进制。
3. 重建启动入口、Info.plist、资源引用、界面层级和生命周期；解码的 NIB 图不是原始 XIB。补齐不可从 IPA 得到的构建配置及未打包文件。
4. 配置并验证业务服务合同、数据模型、认证、播放源和失败状态。静态恢复不证明当前服务器可用，也不恢复服务器源码。
5. 使用 Xcode 26 / iOS 26 SDK 或更新版本进行真正的源代码编译，设置符合当前要求的最低系统版本，完成真机浏览、播放、下载和账号状态验收。
6. 在具备可发布构建后准备 App Store Connect 分发签名、应用记录、测试信息与合规材料，并验证服务器接受和 TestFlight 可安装状态。

恢复数量表示选定范围中的元数据或反编译覆盖率，不表示工程实现、可重编译率或运行行为等价率。原包之外的后端、构建文件和依赖源码仍为未知。
